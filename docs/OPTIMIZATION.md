# Precision 运行时优化

本轮基于已经审查的 2.0.6 + max-su V5 合并版 `ae9d043`，保持 DLL 和公开 API 的版本、虚函数声明、游戏调用点及配置格式。

## 实现与业务约束

| 路径 | 改动 | 保持的行为 |
| --- | --- | --- |
| 主更新、物理前、Havok 后、延迟任务及轨迹列表 | 将逐个 `vector::erase` 改为一次稳定压缩，最坏整理成本从 O(n²) 降为 O(n) | 原顺序逐项执行；完成项立即释放；保留项下次按原顺序执行；各阶段的锁与 deltaTime 保持原位置 |
| 待命中列表 | 在同一次独占锁内按序处理并清空 | 保留原来的更新阶段与处理顺序；消除旧读锁释放到清理写锁取得之间，新命中可能未处理就被清除的窗口 |
| Collision_Add/Remove/ClearTargets 注释 | 直接遍历原载荷中的 token，省去临时 vector 分配 | 只跳过空 token，保留空格、大小写、参数顺序、已有解析和错误处理；重复字段规则保持原实现 |
| V5 命中上下文 | 将入参中已有的载荷 map 移入命中缓存，省去第二次深拷贝 | 调用方载荷仍复制一次形成独立快照；命中目标、注释内容、缓存创建/删除阶段保持原实现 |
| V5 键查询 | 用 string_view 直接查询，省去临时 owning string | 键仍由 map 持有，完整内容比较，包括内嵌 NUL 的显式视图 |
| 自定义参数注册表查询 | 只读查询持共享锁 | 注册仍持独占锁；查询读取当前注册表，无额外缓存失效窗口 |

`ProcessRetained` 在某项抛异常时整理已保留项及尚未处理的后缀，然后重新抛出；与旧循环一样保留当前失败项及未执行项，避免下一次执行遇到整理过程中留下的空指针。当前实现中的任务不会向正在处理的同一容器追加；跨队列任务仍进入原来的目标阶段。延迟任务产生的轨迹仍能在本帧后续的轨迹阶段更新。

命中判重、同 ID 共享冷却、多目标上限、回调次序、hitstop 倍率及冲量延后条件均沿用合并基线。任务整理不会跳帧或改变物理阶段；V5 仍在伤害处理期间向 MSL 提供同一命中的载荷。读档清理沿用原来的清理路径，未引入跨帧游戏对象裸指针缓存。

## 指令集与内存

这次收益来自减少智能指针搬移、map/string 分配和临时数组；这些路径以分支、指针和短字符串为主。原有 Havok 向量计算继续通过库实现。构建沿用 x64 目标，不强制 AVX2/FMA：本轮没有适合批量向量化的数值内核，FMA 还可能改变浮点舍入及边界判定。

## 验证

独立测试将新整理算法与旧 erase 循环逐项比较，覆盖执行/析构轨迹、跨帧保留、共享所有权、异常恢复和随机输入；注释 token 与旧 Tokenize 比较，覆盖空值、连续分隔符、空格和显式 NUL。待命中队列测试通过同步信号控制生产者和处理者，确认处理期间入队会等待，随后保留到下一轮且只执行一次。测试在 Release 模式中仍执行检查。

Release 测试通过；MSVC 19.44 AddressSanitizer 测试通过；Clang 20.1 UBSan trap 模式测试通过。覆盖 3,000 组随机 token 输入、250 组随机队列场景，以及上述确定性时序和并发用例。API 核查通过：13 个标准声明、回调别名、V5 虚函数接口及版本枚举保持一致。DLL 为 AMD64，版本 2.0.6，兼容运行时标记 1.6.1170，四个插件导出保持一致。

测试构建：

```powershell
cmake -S . -B build/ng-merge -DPRECISION_BUILD_TESTS=ON
cmake --build build/ng-merge --config Release --target precision_runtime_tests precision_runtime_bench --parallel 12
ctest --test-dir build/ng-merge -C Release --output-on-failure
& build/ng-merge/Release/precision_runtime_bench.exe
```

以上使用 `MERGE.md` 中已配置依赖的构建目录。在 x64 MSVC 开发环境中，额外验证使用：

```text
cl /std:c++20 /O1 /EHsc /MD /Zi /fsanitize=address tests/runtime_tests.cpp /Febuild/precision-runtime-msvc-asan.exe
clang-cl /std:c++20 /O1 /EHsc /MD /Zi /clang:-fsanitize=undefined /clang:-fsanitize-trap=undefined tests/runtime_tests.cpp /Febuild/precision-runtime-ubsan-trap.exe
```

两者生成的测试程序均成功执行。最初另试的 Clang 20.1 ASan 在 throw/rethrow 用例的 VCRUNTIME 异常展开处退出；最终 ASan 结果采用与插件相同编译器的 MSVC 验证，不将那次退出计作通过。

## 微基准结果

环境：Intel Core i5-13600KF，Windows x64，MSVC 19.44 Release，预热 2 次后取 7 次中位数。每对算法使用相同输入；队列构造和校验排除在计时外；队列计时包含完成项释放，载荷计时包含完整 map 复制、移动和查询。表中时间均为微秒、同一行的整批耗时。

| 场景 | 每批次数 | 原实现 μs | 优化后 μs | 比值（原/新） |
| --- | ---: | ---: | ---: | ---: |
| 32 项队列，50% 完成 | 937 | 458.1 | 329.5 | 1.39× |
| 32 项队列，100% 完成 | 937 | 864.8 | 453.8 | 1.91× |
| 256 项队列，50% 完成 | 117 | 852.7 | 292.4 | 2.92× |
| 256 项队列，100% 完成 | 117 | 1554.2 | 292.1 | 5.32× |
| 4096 项队列，50% 完成 | 20 | 24671.2 | 738.2 | 33.42× |
| 4096 项队列，100% 完成 | 20 | 46156.7 | 819.9 | 56.30× |
| 典型四字段注释遍历 | 5000 | 544.4 | 126.7 | 4.30× |
| 合成 420 字段注释遍历 | 120 | 454.7 | 252.0 | 1.80× |
| 1 个载荷键，每值 48 字节 | 180 | 48.5 | 30.9 | 1.57× |
| 1 个载荷键，每值 2048 字节 | 100 | 45.7 | 22.6 | 2.02× |
| 4 个载荷键，每值 48 字节 | 180 | 159.8 | 104.6 | 1.53× |
| 4 个载荷键，每值 2048 字节 | 100 | 126.0 | 84.3 | 1.49× |

这些数值测量独立算法开销，不能换算为游戏帧率。实际队列长度、字段数、命中频率和引擎调用占比决定整帧收益。随机种子及原始校验值由 `precision_runtime_bench` 输出。

游戏内仍需检查连续攻击、多目标/同 ID 命中、hitstop 后冲量、特殊硬直载荷、轨迹消失、暂停及读档。此文不将独立算法验证视为这些游戏场景已经实测通过。
