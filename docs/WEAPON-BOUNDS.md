# 武器自动长度的局部旋转修复

## 问题与修复

自动武器长度来自模型包围球，采用 `radius + abs(center.y)` 估算。`GetModelBounds` 先遍历符合严格渲染条件的几何体；结果半径为零时，再放宽 `kRenderUse` 和部分 effect shader 的深度写入限制进行备用遍历。

旧备用路径对包围球中心只应用几何体的缩放和平移，遗漏局部旋转。带有旋转和偏移的武器模型可能因此得到错误的中心，影响自动攻击距离及使用该距离的默认武器轨迹。

2.0.8 让两次遍历共用 `ModelBounds::Transform`：先应用几何体完整局部变换，再应用累计父变换，半径依次随两级缩放变化。几何体的局部变换只应用一次。严格遍历的计算规则、备用遍历的触发条件及包围球合并规则保持原样。

## 使用影响

- 仅使用自动长度且落入备用计算的模型会因本次修复改变结果；长度可能变长或变短，取决于模型的旋转和偏移。
- 显式攻击长度配置继续优先。轨迹使用真实碰撞长度时，仍按碰撞胶囊计算。
- 为旧误差设置的补偿倍率可能需要重新校准。
- 长度仍由包围球估算；本次修复恢复坐标变换，未改为逐顶点测量。

## 回归验证

`precision_model_bounds_tests` 直接使用 CommonLib 的 `NiBound` 与 `NiTransform`，覆盖：

| 样例 | 预期 |
| --- | --- |
| 中心 `(0,100,0)`、半径 `10`，局部 Z 轴旋转 180° 并平移 `(0,150,0)` | 中心 `(0,50,0)`、长度 `60`；旧遗漏旋转的结果为 `260` |
| 单位变换 | 输入包围球保持原值 |
| 缩放与平移 | 中心及半径按同一变换更新 |
| 不同的父级与局部旋转、缩放、平移 | 中心 `(13,-101,75)`、半径 `24`，验证变换顺序 |

首个样例已在修复前复现失败，修复后通过；测试也检查输入包围球未被修改。2.0.8 的 Release 构建和全套 7/7 CTest 通过。以上数值来自合成样例，反馈中的原始 NIF 和游戏内表现尚未验证。
